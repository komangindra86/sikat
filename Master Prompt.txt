==================================================
1. ROLE DAN TANGGUNG JAWAB
==================================================

Bertindak sebagai:

- Senior Software Architect
- Senior Go Developer
- Database Architect

- System Analyst
- DevOps Engineer
- QA Engineer

Tugas utama adalah membangun aplikasi production-ready
untuk mengelola seluruh pekerjaan IT rumah sakit.

Nama aplikasi:
SIKAT (Sistem Informasi Kelola Aduan & Tindak Lanjut)

Aplikasi ini bukan sekadar sistem pengaduan.

Aplikasi harus mampu mengelola:
1. Pengaduan gangguan IT.
2. Penanganan dan penugasan pekerjaan IT.
3. Monitoring pekerjaan petugas.
4. Histori kerusakan perangkat.
5. Preventive dan corrective maintenance.
6. SLA dan eskalasi otomatis.
7. Kegiatan internal IT.
8. Inventaris perangkat IT.
9. Laporan kegiatan dan kinerja IT.
10. Integrasi master data SIMRS.

Hasil akhir harus berupa aplikasi yang benar-benar
berfungsi, bukan prototype atau tampilan statis.

8. PENGAJUAN TIKET
==================================================

Flow:

1. Pegawai scan QR.
2. Sistem mengenali lokasi/perangkat.
3. Pegawai memasukkan nama.
4. Unit diisi otomatis jika tersedia.
5. Pegawai memilih jenis gangguan.
6. Pegawai menuliskan kendala.
7. Sistem menanyakan dampak gangguan.
8. Pegawai dapat melampirkan foto.
9. Pegawai mengirim tiket.
10. Sistem membuat nomor tiket.
11. Sistem menentukan prioritas otomatis.
12. Tiket masuk antrean.
13. Sistem mengirim notifikasi.

Nomor tiket:
TKT-2026-000001

Identitas pelapor:
- Nama.
- Unit/bagian.
- Kontak opsional jika diperlukan.

Jangan mewajibkan login.

Sediakan halaman konfirmasi yang menampilkan:
- Nomor tiket.
- Lokasi.
- Jenis masalah.
- Prioritas.
- Link pemantauan tiket.

Gunakan secure access token untuk melihat tiket.

Pelapor hanya boleh melihat tiket miliknya.

Jangan meminta nama pasien, diagnosis,
atau data rekam medis.

==================================================
9. AUTOMATIC PRIORITY ENGINE
==================================================

Prioritas:

LOW = Rendah
MEDIUM = Sedang
HIGH = Tinggi
CRITICAL = Kritis

Pertimbangkan:
- Kategori gangguan.
- Dampak terhadap pelayanan.
- Jumlah pengguna terdampak.
- Ketersediaan perangkat pengganti.
- Dampak terhadap pelayanan klinis kritis.

Jangan hanya menggunakan kategori perangkat
untuk menentukan prioritas.

Contoh:
- Satu komputer rusak tetapi tersedia pengganti:
  Sedang.
- Seluruh komputer satu unit tidak berfungsi:
  Tinggi.
- Gangguan jaringan yang berdampak pada layanan
  klinis kritis:
  Kritis.

Buat configurable priority rules.

Admin dapat mengatur aturan prioritas
tanpa mengubah source code.

Koordinator dapat mengubah prioritas dengan alasan.

Semua perubahan harus masuk histori.

Prioritas kritis:
- Notifikasi segera.
- Alert dashboard.
- Eskalasi kepada koordinator.
- Monitoring khusus.

Sistem tidak menggantikan prosedur darurat rumah sakit.

- Satu tiket hanya memiliki satu penanggung jawab
  utama pada satu waktu.

- Gunakan SELECT FOR UPDATE atau atomic update.
- Cegah dua petugas mengambil tiket yang sama.
- Jika sudah diambil, tampilkan pemberitahuan.
- Koordinator dapat mengambil alih.
- Petugas dapat menambahkan anggota pendukung.
- Semua perubahan penugasan tercatat.

Tampilkan beban kerja petugas.

Siapkan pengaturan kompetensi petugas berdasarkan
kategori pekerjaan, agar petugas dapat memfilter
tiket yang sesuai kemampuannya.

Jangan membuat distribusi tiket manual sebagai
proses wajib.

13. SLA & AUTOMATIC ESCALATION
==================================================

Buat modul SLA configurable.

Admin dapat menentukan SLA berdasarkan:
- Prioritas.
- Kategori.
- Jenis gangguan.
- Unit tertentu jika diperlukan.

Sediakan konfigurasi:
- Target waktu respons.
- Target waktu penyelesaian.
- Waktu operasional.
- Kalender kerja.
- Hari libur.
- Aturan eskalasi.

Jangan hardcode angka SLA.
Nilai default hanya boleh berupa konfigurasi awal
yang dapat diubah admin.

PENGHITUNGAN:

Response time:
Waktu tiket dibuat sampai pertama kali diterima
oleh petugas.

Resolution time:
Waktu tiket dibuat sampai status RESOLVED.

Downtime:
Waktu gangguan sampai layanan dinyatakan pulih,
jika data waktu awal gangguan tersedia.

Buat penghitungan yang membedakan:
- Waktu kalender.
- Waktu operasional.
- Waktu tertunda karena alasan tertentu.

Jangan otomatis menghentikan SLA tanpa aturan
yang dikonfigurasi.

ESCALATION:

Jika target respons terlewati:
- Notifikasi petugas.
- Notifikasi koordinator.

Jika target penyelesaian mendekati batas:
- Pengingat otomatis.

Jika target terlewati:
- Eskalasi.
- Alert dashboard.
- Catatan histori.

Untuk prioritas kritis:
- Eskalasi segera.

Buat background worker untuk memeriksa SLA.

Gunakan database untuk menyimpan status eskalasi
dan mencegah notifikasi duplikat.

Tampilkan:
- SLA berjalan.
- Sisa waktu.
- Persentase pemakaian SLA.
- Status aman/peringatan/terlambat.

SLA breach harus dapat dilaporkan secara bulanan.

16. INTEGRASI SIMRS
==================================================

Sistem harus siap diintegrasikan dengan SIMRS
tanpa menjadikan integrasi sebagai ketergantungan
untuk menjalankan aplikasi pada tahap pertama.

Buat integration layer terpisah.

Target data integrasi:

1. Master unit/departemen.
2. Master ruangan.
3. Master pegawai.
4. Master inventaris/perangkat jika tersedia.

Sediakan kemungkinan metode integrasi:

- REST API.
- Database read-only connection.
- Scheduled data synchronization.
- Import CSV sebagai alternatif.

PRINSIP INTEGRASI:

- Jangan mengubah data SIMRS.
- Gunakan akses read-only jika melalui database.
- Jangan melakukan query berat ke database produksi.
- Jangan membuat foreign key langsung ke database SIMRS.
- Gunakan external_id untuk pemetaan data.
- Simpan hasil sinkronisasi ke database lokal.
- Catat waktu sinkronisasi terakhir.
- Catat error sinkronisasi.
- Sediakan manual sync untuk admin.
- Siapkan mekanisme retry.
- Jangan menimpa data lokal yang memiliki perubahan
  manual tanpa aturan yang jelas.

Buat interface seperti:

OrganizationProvider
RoomProvider
EmployeeProvider
AssetProvider

Implementasi awal menggunakan LocalProvider.

Di masa depan dapat dibuat:
SimrsApiProvider
SimrsDatabaseProvider
CsvImportProvider

Sediakan halaman konfigurasi integrasi.

Jangan membuat integrasi palsu.
Jika koneksi SIMRS belum tersedia, aplikasi harus
tetap berjalan menggunakan master data lokal.
